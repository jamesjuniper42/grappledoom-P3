# Grapple Doom: mouse-only grappling-hook mod for GZDoom

A GZDoom mod where the grappling hook is the only way to move. Inspired by the grapple in Nightmare Reaper and the slide in Ultrakill. Built as a PK3 (a renamed zip) with ZScript, plus a generated UDMF test map.

## Target environment
- GZDoom 4.14.2 on Windows 11. Use the ZScript `version "4.0"` API.
- IWAD: Freedoom Phase 2 (`freedoom2.wad`, BSD licensed) so the mod can be shared without owning Doom 2. Doom 2 also works.
- Run: `gzdoom.exe -iwad freedoom2.wad -file GrappleMod.pk3 +map GRAPPLE1`
- Right mouse must be bound: `bind mouse2 +altattack` (`keyconf.txt` suggests this default).
- Claude cannot run GZDoom here. Nothing is playtested by Claude. The workflow is: Claude edits, the user runs it and pastes the console output or describes what happened, Claude fixes it.

## Layout
```
build.py                 generates the map, sprite and GrappleMod.pk3
grapple_mod/

  traffic.zs             TrackGeom (lane math), TrafficCar (+4 colors), TrafficSpawner

  leap.zs                LeapMancubus (Mancubus that leaps at a distant target)
  ram.zs                 RamCar (vehicle enemy, subclass of TrafficCar) and RamImp (the two riders)
  wave.zs                WaveDirector, WaveTrigger, WaveSpawn (wave survival for GRAPPLE3)
  skid.zs                SkidCannon (replaces the pistol), SkidBolt (slides along the floor)
  mapinfo.txt            registers GrapplePlayer; defines maps GRAPPLE1, GRAPPLE2 and GRAPPLE3; DoomEdNum 30001 = spawner, 30002 = ClusterDemon, 30003 = LeapMancubus, 30004 = RamCar, 30005 = WaveDirector, 30006 = WaveSpawn, 30007 = WaveTrigger
  keyconf.txt            default bind for mouse2; alias `invincible` = `god` (console toggle)
  maps/grapple1.wad      GENERATED by build.py (test yard)
  maps/grapple2.wad      GENERATED by build.py (speedway)
  maps/grapple3.wad      GENERATED by build.py (town, wave survival)
  sprites/*.png          GENERATED by build.py (rope bead; CARxA1..8 = 8-angle car sprites in R/B/Y/G)
run_grapple.bat          launches GRAPPLE1
run_speedway.bat         launches GRAPPLE2
run_town.bat             launches GRAPPLE3
```
- Edit `build.py` to change the map or sprite. Do not hand-edit anything in `maps/*.wad` or `sprites/*.png`; they are overwritten on every build.
- Rebuild after any change: `python3 build.py`. It checks that every sector outline closes into a loop, that the `TRK_*` track constants in `build.py` match `traffic.zs`, and runs a small ZScript lint (balanced brackets; identifiers that are reserved words or shadow Actor members, since ZScript is case-insensitive: a variable `sTop` is the `stop` keyword). It is not a compiler.
- Shipping package: `GrappleMod.pk3` + `freedoom2.wad` + Freedoom's `COPYING.txt`, `CREDITS.txt`, `CREDITS-MUSIC.txt` (keep these with any copy of Freedoom) + `run_grapple.bat` + `README.txt`.

## Design spec (what the user asked for)
- Right mouse fires a hook that travels straight from the crosshair.
- The hook hitscans first to find the hit point. Within 5 m the hit point is the grapple point and it attaches instantly. Farther, the hook visibly flies to the point at 128 units/tic (at least 4 tics, so about 0.2 s at 30 m and 0.6 s at the 80 m max) and then connects and pulls.
- The hook grapples terrain and enemies. On an enemy it pulls the player to it, tracking it while it moves, and stops at its body. Open sky is ignored.
- Ledge assist: if the hook hits the face of a step or ledge whose top is within 3 m above the hit point (with headroom), the pull goes in two legs: straight up in front of the face until the feet clear the lip, then over the lip onto the ledge.
- If it hits a door or button line (a line with a player-use special), activate that line like pressing use, and do not pull the player.
- The hook is the only way to move: no WASD, arrows, strafing or jumping.
- After a pull, the player slides with very little friction. Max speed is clamped to 2x Doomguy's run speed.
- Mouse-only play: left click shoots, right click hooks.
- A floor hit well above the player's feet (for example the infield behind a wall) lifts the player straight up first, then flies to the point, so walls are cleared instead of rammed.
- Speedway (GRAPPLE2): a huge four-lane loop under open sky with traffic; see the Speedway section.

## How GrapplePlayer works (`zscript.zs`)
- Units: 32 map units = 1 meter, 35 tics = 1 second.
- Tuning constants sit at the top of the class: `NEAR_RANGE` (160 = 5 m), `HOOK_SPEED` (128 units/tic) and `MIN_FLIGHT` (4 tics), `MAX_RANGE`, `MAX_SPEED` (30.2 = 2x run speed of about 15.1), `PULL_MIN`, `PULL_ACCEL`, `ARRIVE_DIST`, `MAX_PULL`, `SLIDE_GROUND_KEEP`, `SLIDE_AIR_KEEP`, `SLIDE_STOP`. Change numbers here first when the feel is off.
- State machine (`mstate`): `GS_IDLE`, `GS_PULL`, `GS_SLIDE`.
  - `Tick()` detects a right-click edge from `player.cmd.buttons` (`BT_ALTATTACK`) and calls `FireHook()`.
  - `FireHook()` does a `LineTrace`, rejects open sky, treats shootable actors as anchors (`hookTarget`, re-aimed every tic by `UpdateActorTarget()`), computes `pullTarget`, sets up ledge assist with `TryLedgeAssist()`, then either arrives now or sets `pending` for a distance-based flight time.
  - `HookArrived()` either activates the line (door or switch) or calls `BeginPull()`.
  - During `GS_PULL` the script sets `Vel` straight at `pullTarget` with gravity off. `stuckTics` ends the pull if the player stops making progress.
  - `EndPull()` turns the last real displacement into `slideVel` and enters `GS_SLIDE`.
  - During `GS_SLIDE` the script owns horizontal velocity and measures real displacement each tic, so the engine's floor friction never matters.
- Walking is disabled through the Default block: `Player.ForwardMove 0, 0`, `Player.SideMove 0, 0`, `Speed 0`, `Player.JumpZ 0`.
- The rope is a chain of short-lived `RopeBead` actors spawned each tic.

## Things not yet confirmed in-game
Claude wrote these from memory of the API. Suspect them first when something breaks:
- `Line.Activate(self, side, SPAC_Use)` as the way to trigger doors and switches.
- Zeroing `Player.ForwardMove` / `SideMove` / `Speed` actually stops keyboard walking. (An earlier `TweakSpeeds` override failed to compile in 4.14.2 and was removed.)
- `gameinfo { PlayerClasses = ... }` in `mapinfo.txt` registering the class.
- `LineTrace` flags and `FLineTraceData` fields, and the `skyflatnum` checks.
- Ledge assist (`TryLedgeAssist`) uses `Line.delta`, `Line.frontsector` / `backsector` and `t.LineSide` to find the wall normal and far side; the two-leg lift path is untested in-game. Tune `LEDGE_REACH`, `LEDGE_INSET`, `LEDGE_STANDOFF`, `LIFT_ARRIVE`.
- Enemy hooks use `t.HitActor` and a standoff of both radii + 8 units.
- Traffic (`traffic.zs`) was never compiled or run: `TrackGeom` static functions with `out` parameters, `Array<TrafficCar>` fields, `class<Actor>` assignment from a string, `DoomEdNums` pointing at a ZScript class, `A_Explode` argument order, the `DamageMobj` override signature, `+NODAMAGETHRUST`, `Die(null, null)` and `SetOrigin` on a non-solid actor.
- Careening cars rely on a blocked move being visible as a much shorter displacement than the velocity (no `BlockingLine` use). Non-solid actors are assumed to be stopped by walls (one-sided lines and 64-unit steps) but not by things.
- Player/car impacts use the player's measured velocity (`slideVel` or `lastDisp`) and the car's `cvel`; the thresholds (`closing < 2.0`, launch speed, damage) are guesses.
- Car sprites are generated placeholders (boxy 3D renders). Doom sprite rotation 1 is the car's front, 3 its left side, 5 its back.
- Yellow and white lane-line flats are Freedoom-only (`AQF043`, `AQF062`); with a real Doom 2 IWAD they will show as missing flats.
- Overall feel numbers (pull speed, slide friction, stop threshold) are untuned guesses.

## Speedway (GRAPPLE2) and traffic
- Track: a stadium shape (two 6000-unit straights joined by semicircles of radius 2400 at the median), 16 m wide, four lanes at offsets +192, +64 (traffic counter-clockwise) and -64, -192 (clockwise) from the median. White lane lines, yellow median line, 64-unit (2 m) walls, which are just the step up to the infield and the outside floor, and open sky everywhere. 20 pylons (floor 448) in the infield and outside serve as hook anchors above wall height. Items in the infield and outside reward hooking over the wall. Player start is on the bottom straight in lane +64.
- `TRK_S`, `TRK_R` and `TRK_LANE0..3` exist in BOTH `build.py` and `traffic.zs` (`TrackGeom`); change them together (the build fails if they differ).
- Cars (`TrafficCar`, subclasses Red/Blue/Yellow/Green): shootable, NOT solid (the player passes through; impacts are detected in the player script), ignore the player. They drive by distance along their lane and are placed with `SetOrigin` each tic, using the lane math in `TrackGeom`. Each car slows to stay behind the healthy car ahead in its lane (`SAFE_GAP`, `MIN_GAP`) and cruises at 9-14 units/tic.
- Damage: health 120. At 30 or less the car loses control (`StartCareen`): it veers 25-55 degrees off its lane, drives with real engine movement and explodes when blocked, when it touches another car or a player, or after 70 tics. At 0 health it explodes (`A_Explode(70, 192, XF_HURTSOURCE, false, 48)`), which hurts everything nearby including other cars, so explosions chain.
- Spawner (`TrafficSpawner`, DoomEdNum 30001 in MAPINFO, arg0 = cars per lane, default 12): spawns the traffic at level start (keeping the player start clear) and every 2 s tops up any lane that has lost more than 2 cars, out of sight of the players.
- Player impacts (`GrapplePlayer.CheckCarHits` / `CarHit`): each car has an oriented impact box (half length 64, half width 32). If the player meets the car's FRONT (head-on): damage up to 35, launch up at 14 units/tic, and carry some of the car's velocity. Otherwise (rear-end or side): the player takes on the car's velocity, which breaks their momentum. 12-tic cooldown. The player pulling toward a car hooks it like any enemy.
- Lane math was checked with an independent Python port: lane positions match the road, headings match direction of travel in all four lanes.

## Speedway goal: blue key, locked door, exit
- Blue keycard (DoomEdNum 5) at (0, 0), the middle of the infield, so the player must hook over the wall to get it.
- Exit room in the top-left outside corner (x -6268..-5564, y 2532..3268, floor 64, ceiling 224), walled by one-sided lines with a gap of void around it. Its only entrance is a 5 m wide door in the east wall: `Door_LockedRaise` (special 13, tag 0 = back sector, speed 16, delay 105, `arg3 = 2` = blue keycard per LOCKDEFS), texture `DOORBLU`, use-activated and repeatable. The hook opens it the same way as other doors (`Line.Activate`), so it needs the key too.
- Exit switch (`SW1EXIT`, `Exit_Normal` special 243) on the room's west wall. GRAPPLE2's MAPINFO `next` is now GRAPPLE1 (it was GRAPPLE2 itself); medikit inside the room.
- Unconfirmed in-game: that a hook-activated locked door checks the player's keys, the lock number 2 = blue, and the exit leading to GRAPPLE1.

## Town (GRAPPLE3): wave survival (`wave.zs`, `build_map3` in build.py)
- Built by the user's brief: outdoor roads plus buildings, survive 5 location-triggered waves in a fixed order, spawn-in enemies, nothing stops the player leaving mid-wave, level exit appears after wave 5, health/ammo dropped by enemies, roughly 10-15 minutes. Open questions the user never answered, so these are MY defaults and easy to change: wave contents, the zone route, ring-road reuse, ammo meaning (see below).
- Map: the speedway's ring road, infield and outside (`stadium_world`, `add_pylons` shared with GRAPPLE2), plus eight walk-in buildings in the infield (`add_building`: a solid 9 m block, reachable by hooking its wall near the top so ledge assist lifts the player onto the roof, with a hollow room and a south doorway holding pickups), traffic spawner (12 per lane), a closed exit room in the top-left outside corner (`add_exit_room(locked=False)`, door sector tag 10, `Exit_Normal` switch inside).
- Waves: `WaveDirector` (30005, one per map). Beacon towers (bright 12 m pillars) mark the five zones; each has a `WaveTrigger` (30007; arg0 = wave, arg1 = radius, default 1100). Trigger N only works after wave N-1 is cleared. `WaveSpawn` markers (30006; arg0 = wave, arg1 = 0 Cluster Demon / 1 Ram Car) say where each enemy appears (`TeleportFog`, demons 96 up and woken with the player as target). Cleared when every enemy is dead (`RamCar.exploded` for cars). After wave 5 the director calls `Door_Open` on tag 10 via `level.ExecuteSpecial`. Messages use `A_PrintBold` on the players.
- Default waves: 1 = 3 demons (south outside), 2 = 1 ram car + 2 demons (east), 3 = 5 demons (plaza), 4 = 2 ram cars + 3 demons (north), 5 = 2 ram cars + 6 demons (west, near the exit corner).
- Drops: Cluster Demon drops Stimpack (chance 110/255) and Shell (90); Ram imps drop Clip (120) and Stimpack (70). The Skid Cannon uses no ammo, so ammo drops only matter for the shotgun/chaingun found in the buildings.
- Unconfirmed in-game: `level.ExecuteSpecial` call and Door_Open on a tagged sector, `A_PrintBold` from the director, `DropItem` lines, `SetStateLabel("See")` waking a spawned Cacodemon, ThinkerIterator casts on the marker classes, building geometry (all lines two-sided so rooms are walled by height steps, not one-sided lines), roof access via ledge assist, and all the placement coordinates.

## Cluster Demon (`cluster.zs`)
- `ClusterDemon : Cacodemon` (uses the IWAD's cacodemon sprites, so Freedoom's under Freedoom). DoomEdNum 30002; placed in both maps.
- Speed: 45.3 units/tic (3x run) beyond 640 units (20 m) from its target, 7.55 (0.5x) inside; `UpdateChaseSpeed()` eases by `SPEED_STEP` 3 per tic. See state is 1-tic frames so `A_Chase` Speed = units per tic.
- Fire rate about 2x: Missile windup 9 tics (Cacodemon 15) plus attack check every tic.
- `ClusterBall`: projectile, on Death explodes `A_Explode(70, 128, 0, false, 32)` (rocket-sized, does not hurt the shooter), then `SpawnBurst()` throws 3 `ClusterBomblet`s forward of the shot's angle: +-30 degrees, speed 7-13, Vz 6-11, Gravity 0.7. Bomblets share the Death state (explode on impact) and do not burst again.
- Unconfirmed in-game: Cacodemon subclassing and 1-tic See frames, `A_SpawnProjectile`, `virtual SpawnBurst` override, `-NOGRAVITY` in Default, `Projectile;` plus Gravity, DoomEdNum 30002. All balance numbers are guesses.

## Leaper (`leap.zs`)
- `LeapMancubus : Fatso` (IWAD mancubus sprites). DoomEdNum 30003; two placed in GRAPPLE2 only (the yard is too small for a 30 m trigger).
- `See` is 12 four-tic frames calling `ChaseOrLeap()`: if cooldown is over (35 tics, counted in `Tick()`), it is on the ground, the target is over 960 units (30 m) away and visible, it calls `BeginLeap()` and jumps to `Leap`.
- `BeginLeap()` sets Vel from `GetGravity()`: vz = sqrt(2*g*160) for a 5 m peak, hs = 320 / airtime for 10 m forward on level ground, aimed at the target at takeoff.
- `Leap` state runs only `LeapTick()` (never `A_Chase`), so it cannot start an attack mid-jump; `bNoPain` is set until it lands so a flinch cannot change state. Lands when vz <= 0 and on the floor (or after 90 tics).
- Debug: console `leap_debug 1` (CVARINFO) prints a line each time a leaper starts a leap. No line means the conditions never held (not awake, no sight, under 30 m, cooldown).
- Unconfirmed in-game: `State` return from action blocks, `FindState("Leap")` (was `ResolveState`, which is an `action` function and likely returned null from a plain method), `bNoPain` toggling, `GetGravity()` scale (jump height/distance may be off), `FATT G` as the airborne frame, DoomEdNum 30003, placement coordinates.

## Ram Car (`ram.zs`)
- `RamCar : TrafficCar` (so `GrapplePlayer.CheckCarHits` handles player impacts and hooks treat it as a shootable anchor). Sprite `CARK` (dark car, generated by build.py as color K). DoomEdNum 30004; three placed on the speedway road. `selfDriven = true` makes `TrafficCar.Tick` skip lane driving.
- Body is `+INVULNERABLE`; only its two `RamImp` riders (health 60 each, TROO sprites, spawned in `PostBeginPlay`, positioned every tic at +-22 units along the heading, 38 up) can be killed. Riders turn to face the player and throw `DoomImpBall` every 40-80 tics within 50 m and with line of sight.
- Driving: only hunts a player within 4000 units. Top speed 14, accel 0.35, brake 0.8. Heading change per tic = `TURN_SLOW 3.5` blended to `TURN_FAST 1.6` by speed, and scaled to 0 when stopped, so it swings wide at speed. Aims at the player plus a short lead. If the player is more than 120 degrees off the nose it commits to one turn direction (`commit`) and lifts to 75% speed, which is the long arc after a dodge.
- Terrain: it moves with real engine movement (Vel set from heading and speed each tic); displacement under half the expected means blocked. Then `OnBlocked()` enters reverse (`phase 1`, 30 tics at -7, +10 per repeat hit up to +30) swinging the nose toward the player (random side on repeats), then drives forward again at the new angle.
- Death: when both riders are dead (`phase 2`) it veers a random +-70 degrees and drives straight, exploding (`Explode()`, which also kills any rider, clears invulnerability and calls `Detonate()`) when blocked, on touching a player, or after 70 tics.
- Unconfirmed in-game: `+INVULNERABLE` plus `Die(null, null)`, riders as non-solid shootables hit by projectiles and hitscan, `A_FaceTarget(25)` and `A_SpawnProjectile` from a rider, `SetStateLabel("Missile")` from Tick, blocked detection via displacement for non-solid actors, riders' z offsets against the sprite roof, placement coordinates, and all balance numbers.

## Skid Cannon (`skid.zs`)
- Replaces the starting pistol: `Player.StartItem "SkidCannon"` / `Fist` and `Player.WeaponSlot 2` in the GrapplePlayer Default block. Uses plasma rifle sprites (PLSG/PLSF/PLSS/PLSE) and sounds; no ammo (`AmmoUse 0`).
- Fire rate matches the plasma rifle: `PLSG A 3 FireSkid(); PLSG B 20 A_ReFire;` (one shot per 3 tics held).
- `SkidBolt` is a plasma-like projectile (speed 25, damage 5). Its `Tick()` override checks `vel.z < 0 && pos.z + vel.z <= floorz`; if so `StartSlide()` zeroes vel.z, renormalizes horizontal velocity to full speed, hovers 4 units above the floor and keeps going. While sliding it samples the floor at the next position: rises up to 24 units are climbed, larger ones are left alone so the engine blocks the move and the bolt explodes (wall). It explodes on enemies via the normal missile code, and burns out after 175 tics (5 s) of sliding (`sliding` is cleared before `ExplodeMissile` so `Super.Tick()` keeps running the Death state; an earlier version froze there). A shot fired straight down just explodes.
- Unconfirmed in-game: the `Player.StartItem`/`WeaponSlot` in a subclass REPLACING the inherited pistol (if the pistol is still there, add it back as an issue), `SpawnPlayerMissile`, `SetSafeFlash` call, `SecPlane.ZAtPoint`, the Tick-override floor detection, sliding over slopes/steps, and plasma sprites existing in Freedoom under those names.

## Working conventions
- Ask the user for exact GZDoom console errors when a build fails, and match the 4.14.2 API.
- Make the smallest change that fixes the reported problem, then rebuild with `python3 build.py` and send the new `GrappleMod.pk3`.
- Keep Freedoom's license files with any copy of `freedoom2.wad`.
- Windows quirks seen so far: `cmd.exe` cannot use `\\wsl.localhost\...` as a working directory (the launcher uses `pushd "%~dp0"`); copying from Windows into WSL through Explorer creates `*:Zone.Identifier` files, so add `*:Zone.Identifier` to `.gitignore`.
- GitHub limits: 100 MB per pushed file. `freedoom2.wad` is about 28 MB, which is fine. Attach big zips to a GitHub Release.
